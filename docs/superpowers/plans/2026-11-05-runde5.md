# Runde 5 – Merkliste, Einführung, ohne Kacheln, neue Schrift, Aufräumen

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lukas Wünsche vom 05.11.2026 umsetzen (Merkliste kategorisieren, Einführung beim
ersten Start, keine Kacheln mehr, „Alles löschen“ mit Bestätigung, Schrift Fraunces +
Nunito Sans), eigene Verbesserungen ergänzen, den Code von den alten Designs befreien und
als neue Version per Fingertipp ausliefern.

**Architecture:** Logik (Kategorien, Gruppen, Teiltext, neue Speicherfelder) kommt in den
Swift-Kern `GeschenkeCore`, weil nur er auf Linux testbar ist. Die Zuordnung Stichwort →
Oberbereich wird aus `app/vokabular.py` erzeugt (eine Quelle, ein pytest wacht über
Gleichstand). Die Oberfläche bleibt SwiftUI im Zuhause-Stil; der Entwurf läuft vorher als
HTML-Demo über die Zeigeseite und den Agenten `design-pruefer`.

**Tech Stack:** SwiftUI (iOS 26), Swift-Paket `GeschenkeCore` (XCTest auf Linux in CI),
Python 3.14 + fontTools (Schriften), pytest (Server), GitHub Actions (Build + Release).

**Spec:** Lukas Auftrag (Ziel vom 05.11.2026) + `DESIGN.md` + `CLAUDE.md` (Grundbausteine).

## Entscheidungen (von Claude getroffen, Luka hat freie Hand gegeben)

- **Kategorien automatisch** aus den Stichwörtern der Karte: erster Tag mit Oberbereich →
  dessen Name ohne Emoji („Küche & Kochen“), sonst „Sonstiges“. Kein Pflegeaufwand für Luka.
  Umschalter oben „Personen | Kategorien“, die Wahl wird gespeichert.
- **Einführung:** 3 Seiten, nach dem Startbildschirm, nur beim ersten Start, „Überspringen“
  immer sichtbar, in den Einstellungen wiederholbar (Apple HIG: kurz, überspringbar, nicht
  wiederholt zeigen, wiederholbar). Eigenes Blättern per Knopf statt `TabView(.page)`, damit
  die Übungskarte auf Seite 2 waagerecht gezogen werden kann, ohne die Seite zu wechseln.
  Die Übungskarte zeigt kein erfundenes Produkt (Grundbaustein 1), nur das Geschenk-Motiv.
- **Kacheln:** „Zuletzt gemerkt“, „Deine Leute“, Wischen-Liste, Profil-Liste, Merkliste,
  Profil-Seite, Sammelauswahl, Einstellungen und Gewichtung verlieren ihre Kartenflächen.
  Inhalte stehen offen auf dem Hintergrund, getrennt durch Abstand und feine Linien.
  **Bleibt:** die Hauptkarte „Geschenk finden“, weil die Katze auf ihrer Kante schläft
  (Erkennungsmerkmal, DESIGN.md 5), und die Wischkarte (sie ist das Produkt).
- **Schrift:** wie in DESIGN.md 3 entschieden. Fraunces als statische Instanz (wght 700,
  SOFT 100, WONK 0, opsz 28), Nunito Sans statisch in 400/600/700/800 (opsz 12, wdth 100).
  Fraunces nur für Seitentitel, Abschnittsüberschriften, Einführung und Navigationstitel.
- **Eigene Ideen:** (a) Merkliste „gekauft“ abhaken (Wischen nach rechts oder Menü),
  gekaufte rutschen in ihrer Gruppe nach unten; (b) Teilen: einzelne Idee per Menü, die
  Liste einer Person per Knopf in der Gruppenüberschrift (Text mit Titel, Preis, Link);
  (c) leere Merkliste mit Knopf „Zum Wischen“ (offener Prüfer-Vorschlag); (d) freundlicherer
  Text statt „Server wacht auf …“ (offener Prüfer-Vorschlag); (e) Navigationstitel in Fraunces.

## Global Constraints

- Grundbausteine 1–11 aus `CLAUDE.md`; besonders 1 (nichts Erfundenes), 10 (nur auf dem Handy).
- DESIGN.md: keine Emojis, Palette nur aus `docs/design/palette-zuhause.md`, Animationen ≤ 300 ms,
  keine Federn, „Bewegung reduzieren“ = Überblenden, Tippflächen ≥ 44 pt, Textstile statt fester
  Größen, lange deutsche Wörter nie abschneiden, keine Gedankenstriche als Satzzeichen.
- Neue Felder in `AppDaten`/`MerkEintrag` immer mit `decodeIfPresent` lesen (sonst landen alte
  Daten in `appdaten.kaputt-*.json`).
- Swift-Dateien im Repo sind LF; Python unter Windows mit `newline=''` schreiben.
- Arbeitszweig `runde5`; iOS-Build auf dem Zweig nur per `gh workflow run ios-build.yml --ref runde5 -f runner=macos-15`.

## Review Focus

1. Alte `appdaten.json` ohne `gekauft`, `merkOrdnung`, `einfuehrungGesehen` muss vollständig laden → Test `testAlteDatenOhneNeueFelder`.
2. Karte ohne bekannte Tags (nur Lebenslagen oder leer) → Kategorie „Sonstiges“, Gruppe am Ende → Test `testSonstigesAmEnde`.
3. „Alles löschen“ darf nie ohne Bestätigung löschen, auch nicht im Blatt aus der Wischansicht → Review am Code (UI, kein Test).
4. Einführung darf nach dem Überspringen beim nächsten Start nicht wiederkommen, auch wenn die App direkt danach beendet wird (sofort speichern) → Test `testEinfuehrungGesehenRundreise`.
5. Vokabular ändert sich auf dem Server, App-Tabelle veraltet → pytest `test_bereiche_swift_aktuell` schlägt fehl.
